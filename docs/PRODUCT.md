# 产品定义：从一个点，看见整个局面

## 产品承诺

决策内阁帮助用户更清楚地做决定，不替用户决定。

它把“答案生成”改造成一条可讨论、可追溯、可复盘的认知过程：

1. 从一个具体问题进入；
2. 区分事实、假设、未知和证据缺口；
3. 展开每个选择与它购买、放弃的未来；
4. 识别直接代价、机会成本、二阶效应和不可逆承诺；
5. 看见相反力量、反馈回路、盛衰转换与承载力；
6. 构造局势演化路径和领先信号；
7. 邀请不同方法视角真实交锋；
8. 把决定权交回用户，并通过日志复盘。

## 私董会不是“顾问轮流回答”

产品把一场私董会固定为四轮，每轮都形成可被下一轮消费的公开纪要：

| 轮次 | 议事职责 | 结构化结果 |
| --- | --- | --- |
| 第一轮 · 事实定界 | 区分事实、推断和未知；每位顾问提出可被质疑的初步判断 | 各方观点、小结论、共识、非共识 |
| 第二轮 · 聚焦争议 | 把上一轮非共识变成具体议题，让支持、反对和修正直接交锋 | 议题、各方明确立场、共识、非共识 |
| 第三轮 · 压力测试 | 检验代价、反证、最坏情景、二阶效应和转向信号 | 仍成立的判断、被挑战的假设、演化信号、证据缺口 |
| 第四轮 · 条件式收束 | 说明什么条件下选什么，形成可逆下一步和停止条件 | 条件性结论、行动、少数意见、决定权归属 |

每轮运行顺序是 `agenda → advisor reply chain → round_summary`。顾问按序看到同轮此前发言，并在发言中标出回应对象和立场：`propose`、`support`、`challenge`、`refine` 或 `abstain`。纪要必须保留每一方的观点，不能只剩一段看似圆满的综合文本。

### 用户是参会者，不是问答入口

每轮之间，用户可以选择四种参与方式：

- `answer`：回答委员会刚提出的问题；
- `add`：主动补充事实、约束、数字、感受或自己的判断；
- `focus`：指定下一轮必须深入的争议；
- `listen`：暂不发言，让顾问继续内部讨论。

`listen` 不等于同意。即使用户没有提供新信息，下一轮也会从上一轮的非共识、共识与下一轮焦点继续推进，而不是重新回答原问题。

### 反重复是产品行为

系统比较同一顾问的新发言与其历史发言。高度重复时会带着“必须指出新增反证、条件或立场变化”的要求重试一次；仍然重复时，顾问明确弃权，等待新证据，而不是换词复述。讨论质量来自新增信息和真实分歧，不来自字数。

## 三个主场景

### 商业经营

重点是顾客价值、单位经济、现金流、资本配置、组织承载力与可逆验证。

### 金融投资

重点是原始披露、数据时点、三表联读、估值区间、组合风险、流动性、反证与退出条件。产品不做收益承诺，不在缺少实时数据时假装掌握行情。

### 人生转折

重点是长期方向、关系责任、身份执著、选择的生活方式、不可逆代价与调整空间。产品不做命运保证。

## 阴阳循环的产品化定义

“阴阳”在产品中不是预测术，而是动态系统语言：

- 相反力量：增长/承载、速度/稳定、控制/赋能、收益/风险；
- 消长：一方增强时另一方如何被压制或积蓄；
- 转化：优势在什么阈值后变成负担；
- 时位：同一动作在不同阶段为何可能意义相反；
- 过与不及：不是追求静态平均，而是寻找当前阶段的分寸。

任何阴阳判断都要尽量翻译成可观察信号和反馈机制，不能取代事实或专业尽调。

## 不做什么

- 不输出“AI 已替你算出唯一答案”。
- 不伪造实时行情、财务数字、概率、经典原文或名人原话。
- 不把用户的私人资料写入公开 demo、fixture 或 README。
- 不把灵性、传统文化或心理学变成新的权威依附。
- 不承诺投资收益、健康效果、法律结果或命运走向。
- 不把顾问并列生成的相似回答包装成“委员会讨论”。
- 不把用户沉默解释为同意，也不为了整齐而抹去少数意见。
- 不把静态 GitHub Pages Demo 描述成可供外部宿主连接的远程 MCP 服务。

## 进入用户已有的智能体工作台

Decision Cabinet 同时提供默认只读、无状态的 MCP server，使 Codex、Claude Code、DeepSeek Harness、Hugging Face Tiny Agents 与 ML Claw/OpenClaw 等宿主能调用同一套决策工具。server 默认使用 stdio，也可仅在 loopback 启动 Streamable HTTP；腾讯 WorkBuddy 的远程 Connector 仍需使用者配置 HTTPS 与鉴权反向代理，静态 Demo 不承担这个角色。

接入的目标是让产品出现在用户已经使用的工作台中，而不是要求用户更换模型。宿主负责模型与会话，Decision Cabinet 负责可审查的知识、决策结构、四轮协议和顾问发言 brief。完整边界见 [智能体接入](INTEGRATIONS.md)。

## 成功标准

一次讨论成功，不是因为用户服从了建议，而是因为用户能够清楚说出：

- 我真正要决定什么；
- 我依据哪些事实，还有哪些未知；
- 每个选择得到什么、失去什么；
- 哪些信号会让我改变判断；
- 什么条件下我会停止、退出或回滚；
- 我能准确说出各方哪里一致、哪里不同，以及什么证据会改变他们的立场；
- 为什么这个决定最终由我承担。
